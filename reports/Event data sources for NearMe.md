# Mine free calendar feeds before buying data

NearMe's best new event sources are free and already structured, not paid aggregators: library event platforms (BiblioCommons, LibCal, Communico), CivicPlus government iCalendar feeds, university and venue calendar hosts (Trumba, 25Live, Tockify), the RunSignup race API, and the USDA farmers-market directory. Each gives real start times or an explicit all-day flag, a source URL per event, and costs nothing per call. The research confirmed two of them live in the Boca Raton market. The Palm Beach County Library System's BiblioCommons gateway returned clean JSON with ISO start and end times without a key, and the City of Boca Raton's CivicPlus site exposes the standard `/iCalendar.aspx` feed. The commercial side is thin. Only Ticketmaster has an open discovery API. JamBase is the only vendor with a published commercial price, and its $500/month floor is about $10 per city across 50 cities for music alone, more than three times NearMe's $3 per-city AI budget. Everything else (Evvnt, SeatGeek, Bandsintown, PredictHQ) is sales-led, partner-gated, or bans the caching NearMe's catalog depends on. The biggest structural gain is to fix discovery rather than add vendors. Replacing the flaky Overpass step with Wikidata official-website lookups plus platform fingerprinting would unlock all the free feeds at once. Swapping SerpApi's degraded events box for a cheap SERP API used only to find calendar pages would cut search cost by an order of magnitude. Commercial-reuse terms are the main open risk: none of the government, library or race sources state an explicit commercial licence.

## What the notes actually verified, and what they only claim

The four research notes vary in how strong their evidence is, so every recommendation below carries one of three labels. **Verified** means a researcher fetched the live endpoint or the vendor's own page. **Vendor-stated** means the claim comes from a vendor's documentation and has not been tested. **Unverified** means it comes from third-party summaries or search snippets, or the primary page returned 403. Many pricing figures fall into that last group: PredictHQ, SeatGeek terms, SerpApi plans, Serper, Tavily, Mindbody, and the Evvnt June 2026 announcement were never read first-hand. No source was tested end to end against a Boca Raton query for yield or for cost per verified event, and no government or library terms-of-use page was read.

Only a handful of findings were confirmed against live endpoints. The **BiblioCommons gateway** (`gateway.bibliocommons.com/v2/libraries/pbclibrary/events`) returned title, ISO start and end times, branch location, description, id, series id, registration counts, event types and audiences, with October 2026 events present ([PBCLS events](https://pbclibrary.bibliocommons.com/v2/events); researcher fetch 2026-10-01). The **CivicPlus iCalendar page** exists on myboca.us ([City of Boca Raton calendar](https://www.myboca.us/calendar.aspx)). A per-category Town of Palm Beach feed carried DTSTART/DTEND with `TZID America/New_York`, SUMMARY, LOCATION, UID and URL. It mixed timed events with all-day `VALUE=DATE` events, and its DESCRIPTION is often only a link back to `calendar.aspx?EID=n` ([Town of Palm Beach iCalendar](https://www.townofpalmbeach.com/iCalendar.aspx)). That mix suits the honesty rule well: timed entries display their time, and date-only entries map directly to "time not listed." One counter-finding: `/rss.aspx` on the same site redirected to a login, so not every CivicPlus endpoint stays public.

## Free structured feeds cover most of the gap

### Libraries are the richest free source in any US city

Library platforms are concentrated among a few vendors, which makes them predictable to integrate. BiblioCommons officially offers customers an Events API key, but the gateway above worked without one. That makes the data easy to reach and the terms ambiguous ([BiblioCommons feature sheet](https://resources.bibliocommons.com/hubfs/Resources/Feature%20Sheets/BiblioCommons_BiblioEvents_Feature-Sheet_FIN.pdf)). LibCal publishes per-calendar iCal subscribe URLs of the form `ical_subscribe.php?cid=…&k=…`, with the key printed on the public page ([RDP library answer](https://answers.rdpolytech.ca/faq/205887)). Its official API needs OAuth and caps results at 500 events ([APIs for Librarians](https://www.apis4librarians.com/libcal/upcoming-events)). Communico's legacy feeds were retired in favor of an authenticated API ([Communico College](http://communicocollege.com/1149)), yet one Florida aggregator lists Alachua County's Communico instance as no-auth JSON ([GainesvilleEvents](https://gainesvilleevents.com/sources/)). An open-source project already fingerprints these three platforms across about 1,400 branches and 110 systems, so the discovery method has been proven at scale ([agupt/mylibrary-events](https://github.com/agupt/mylibrary-events)). Library events skew toward family, arts and community programming with exact times, which fills the feed's daytime and kids gaps. The Boca Raton Public Library's own platform was not identified. The lawful path is to request the sanctioned BiblioCommons key and treat the unauthenticated gateway as a stopgap.

### CivicPlus and campus calendar hosts follow fixed URL patterns

CivicPlus works because every CivicEngage site exposes `/iCalendar.aspx`, and CivicPlus documents subscribing by copying a calendar's link ([CivicPlus help](https://www.civicplus.help/municipal-websites-central/docs/use-rss-feeds-from-modules)). The same path was found on sites in Virginia and California ([Vinton](https://va-vinton.civicplus.com/iCalendar.aspx), [Blythe](https://www.cityofblythe.ca.gov/iCalendar.aspx)). Council and commission meetings dominate these feeds, so NearMe would need to filter by category, which costs nothing in AI. Granicus/Vision sites offer only RSS, with dates embedded in item titles ([ByteMasterPro/local-calendars](https://github.com/ByteMasterPro/local-calendars)). That feed is lower quality and needs strict parsing so no time is invented. Universities have cleaner options than Localist alone. 25Live Publisher serves `.ics`, `.rss` and JSON at `25livepub.collegenet.com/calendars/<webname>` ([25Live help](https://25livepub.collegenet.com/help/subscribe)). Trumba serves `trumba.com/calendars/<webname>.ics` and supports custom date-range feeds ([Trumba](https://www.trumba.com/help/api/customfeedurls)). For bars and small venues, Tockify exposes `tockify.com/api/feeds/ics/<id>` ([Tockify](https://tockify.com/)), a natural first probe in NearMe's existing venue scraper before it falls back to LLM extraction.

### RunSignup and USDA cover two verticals nothing else reaches

RunSignup is the only clean, documented, geographic API among the niche verticals. "Get Races" takes a zipcode and radius, a date range and `modified_since`, and returns street address, race URL and timezone-correct start times ([RunSignup Get Races](https://runsignup.com/Api/races/GET)). It is US-only, which fits NearMe's US-first launch, and it requires OAuth 2.0 since April 2026 ([RunSignup Getting Started](https://runsignup.com/API/GettingStarted)). Its docs free the API code itself but explicitly exclude RunSignup content. Rate limits and commercial redistribution terms are not stated, so NearMe needs a partner or affiliate key before shipping ([API Keys](https://runsignup.com/API/ApiKeys)). The USDA Local Food Portal offers a REST and CSV farmers-market directory behind a requested key ([USDA data sharing](https://www.usdalocalfoodportal.com/fe/datasharing/)). Its weakness is honesty rather than legality: listings are self-reported, and hours are seasonal free text. NearMe should only show a time when the text gives one, and should confirm against each market's own site. The endpoint returned 403 to the researchers, so its radius parameters are unverified.

### Discovery, not data, is the broken link

Every free feed above depends on knowing the official website for a city, library or campus, and that step currently runs through Overpass, the flaky one. The notes propose a reproducible replacement. Pull homepages from Wikidata's official-website property (P856), with OSM as fallback. Probe known paths: `/iCalendar.aspx`, `/events/?ical=1`, `/wp-json/tribe/events/v1/events`, LibCal `ical_subscribe.php`, `*.bibliocommons.com`, Trumba and 25Live embeds. Cache hits per city and sync with ETag/If-Modified-Since. The Gainesville aggregator shows this mix (CivicPlus iCal, Google Calendar ICS, Communico JSON, Squarespace `?format=json`, TEC REST) working in one Florida city, and reports that most sources permit bots via robots.txt ([GainesvilleEvents sources](https://gainesvilleevents.com/sources/)). Wikidata-based discovery itself is untested. It is the one engineering bet in this plan, but it costs no API money and runs once per city.

## Search APIs should find calendars, not events

SerpApi's standalone Google Events engine is gone. Its changelog says event data now survives only in the `events_results` field of regular Google Search ([SerpApi changelog](https://serpapi.com/blog/serpapi-weekly-changelog-august-24-30-2026/)). DataForSEO retired its own endpoint on September 15, 2026, because Google dropped the Events tab ([DataForSEO](https://dataforseo.com/update/deprecation-of-google-events-serp-api)). That explains NearMe's observation that the box appears in only about half of cities. SerpApi's documentation still lists `time` and `link` fields ([SerpApi docs](https://serpapi.com/events-results)), while NearMe's production results lack both. The conflict is unreconciled, and the fields are evidently sparse in practice. SerpApi is also the priciest SERP option, reportedly about $9–25 per 1,000 searches (unverified, [ScrapeGraphAI](https://scrapegraphai.com/blog/serpapi-pricing)). It also carries legal tail risk. Google's DMCA suit was dismissed in July 2026 and refiled in narrower form, with a hearing set for October 13, 2026 ([Search Engine Journal](https://www.searchenginejournal.com/court-dismisses-googles-dmca-claims-against-serpapi/583033/)).

The cheaper pattern is to use search only to find the pages that publish calendars, then parse those pages for free. Serper is reported at $0.30–1.00 per 1,000 queries with 2,500 free ([ColdIQ](https://coldiq.com/blog/serper-pricing)), and DataForSEO at $0.60 per 1,000 standard ([Octoparse](https://www.octoparse.com/blog/best-serp-api)). Both are unverified third-party figures. At those rates, 30 discovery queries per city per month costs about one to three cents. Brave is $5 per 1,000 but bans permanent storage without an unpublished storage plan ([Brave](https://brave.com/search/api/)), which rules it out for a persisted catalog. Bing's search APIs were retired in August 2025 ([PPC Land](https://ppc.land/microsoft-ends-bing-search-apis-on-august-11-alternative-costs-40-483-more/)), and Google Custom Search closes on January 1, 2027 ([Octoparse](https://www.octoparse.com/blog/google-official-search-api)). Anthropic's web search tool costs $10 per 1,000 searches plus tokens. It supports `user_location`, `allowed_domains` and `max_uses` caps, and it requires citations to be shown ([Anthropic docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)). That makes it a usable per-city fallback within a $3 budget only if NearMe requires the date string to appear in the fetched source, since LLMs are known to make stale-date errors ([arXiv 2504.01153](https://arxiv.org/abs/2504.01153)). Web Data Commons offers a free seed list of event-publishing sites: 14.1 million URLs with schema.org Event markup across 399,466 hosts. The snapshot dates from October 2024, so only the hostnames are reusable, and usage rights require contacting WDC ([WDC Event subset](https://webdatacommons.org/structureddata/2024-12/stats/schema_org_subsets.html)).

## Commercial vendors are gated, priced out, or ban caching

The commercial market has not opened up since Eventbrite closed public search in 2020 ([Eventbrite API notice](https://groups.google.com/g/eventbrite-api/c/FT2MsDswdrA)). **JamBase** is the only vendor with self-serve commercial pricing. The free Developer tier is non-commercial; Startup is $500/month for 20,000 calls, enough for a daily refresh across 50 cities. It covers 91,000+ venues and offers a 14-day trial ([JamBase pricing](https://data.jambase.com/pricing)). But it covers music only, skews to ticketed shows, and its caching terms were not read. **Evvnt's Publisher API** syndicates listings from 2,200+ calendars, including Ticketmaster, AXS and Bandsintown content ([Evvnt network](https://evvnt.com/integrations/data-distribution-event-advertising/), [Evvnt API](https://api.evvnt.com/)), but price and display terms need a sales call. **PredictHQ** is built for demand forecasting. Its terms forbid caching or storing its data without written agreement ([PredictHQ Terms](https://www.predicthq.com/legal/terms)), which conflicts directly with NearMe's Supabase catalog, whatever its reported $75 Lite price. **Bandsintown** restricts its API to artists and their agents, with commercial use only by written consent via API@bandsintown.com ([Bandsintown terms](https://corp.bandsintown.com/data-applications-terms)). **SeatGeek** routes access through a Partner License Agreement via hi@seatgeek.com ([SeatGeek partner terms](https://seatgeek.com/partner-terms)). **Songkick** takes no new keys, and **Setlist.fm** covers only past shows and bans commercial use.

Ticketmaster deserves a compliance check of its own. Its terms forbid storing event content "beyond reasonable periods needed to provide the service." They also offer an Impact affiliate ID on ticket links, which would turn NearMe's existing link-outs into revenue. The bulk Discovery Feed is restricted to authorized clients via devportalinquiry@ticketmaster.com ([Ticketmaster terms](https://developer.ticketmaster.com/support/terms-of-use/), [Discovery Feed](https://developer.ticketmaster.com/products-and-docs/apis/dc-dataFeeds/)). Several sources have no lawful commercial path at all. These include public Facebook events, available only to academic researchers via the Meta Content Library ([Meta](https://transparency.meta.com/researchtools/meta-content-library/)); TikTok's academic-only API; and Resident Advisor, Luma, Posh, AllEvents and Roaming Hunger, reachable only through third-party scrapers or undocumented endpoints. Mindbody needs each studio owner to activate access ([Mindbody community](https://developers.mindbodyonline.com/community/questions/46/how-much-are-api-fees.html)), and Strava exposes club events only to authenticated members ([Strava changelog](https://developers.strava.com/docs/changelog/)). Trivia companies and comedy open-mic lists, such as Geeks Who Drink's roughly 1,100 venues ([GWD FAQ](https://www.geekswhodrink.com/faq/)) and Badslava ([About](https://www.badslava.com/questions.php)), publish no API. The Geeks Who Drink venue page the researchers checked showed a weekday but no time, so a partnership is the only route that satisfies both the ToS and the honesty rule.

The order follows from NearMe's constraints. The top five cost nothing per call and need no LLM extraction, since they are already structured. They emit real times or an explicit date-only flag, and every event carries a source URL. That serves the cost goal and the honesty rule together. Discovery ranks first because sources 2 through 5 all depend on it. Sources 6 and 7 add breadth at trivial cost but need verification gates. Paid and partner sources come last. JamBase is the only one with a known price, and it fails the per-city budget unless a 14-day Boca trial shows dense small-venue coverage that the free feeds miss.

## Conclusion

The evidence reverses the usual instinct to buy an aggregator. In 2026 the commercial event-data market is partner-gated almost everywhere, while the public sector and campus calendar vendors have standardized feed URLs that nobody needs permission to subscribe to. NearMe's competitive edge is therefore engineering: reliable per-city discovery and fingerprinting turn hundreds of free, timed, linked feeds into a dense catalog at near-zero marginal cost. That catalog is the "works anywhere" property a paid vendor would only rent back. Paid sources would mostly duplicate it, apart from music.

Two unresolved risks should shape the next step. First, no source gives explicit commercial-reuse permission. NearMe's position should be to store facts plus a link, respect robots.txt, keep volume low, and ask BiblioCommons, RunSignup and USDA for sanctioned keys before scaling. Second, every yield figure here is projected rather than measured. Before committing engineering time, NearMe should run a one-week Boca Raton and Delray pilot that counts events with a verifiable time and source link per dollar across library, CivicPlus, RunSignup, Serper-discovered venues and Anthropic web search.
